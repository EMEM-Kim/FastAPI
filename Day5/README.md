
## 📑 1. Spec API (OpenAPI / Swagger)
### **Spec API란?**
애플리케이션이 제공하는 인터페이스(Endpoint, 데이터 구조, 인증 방식 등)를 표준화된 형식으로 명세화한 것입니다. 현대 웹 개발에서는 보통 **OpenAPI Specification(OAS)**을 의미한다.

### **주요 특징**
* **언어 독립성:** HTTP 기반 서비스라면 어떤 언어로 작성되었든 동일한 규격으로 설명 가능하다.
* **자동 문서화:** 코드에 Type Hint를 추가하면 `Swagger UI` 같은 대화형 문서가 자동으로 생성된다.
* **협업 효율:** 프론트엔드와 백엔드가 API 명세를 공유하여 병렬 개발을 가능하게 한다.

## 🔍 2. dmypy (Mypy Daemon)
### **dmypy란?**
Python의 정적 타입 검사기인 `mypy`를 서버 모드(Daemon)로 실행하는 도구이다.

### **주요 특징**
* **성능 최적화:** 프로그램이 메모리에 상주하며 변경된 파일만 체크하므로, 일반 `mypy`보다 검사 속도가 압도적으로 빠르다.
* **개발 경험(DX):** 대규모 프로젝트에서 타입 검사 시간을 획기적으로 단축하여 실시간 피드백을 제공해준다.

## 🐍 3. Pythonic Mastery (공식 문서 기반)
### **classmethod**
* **개념:** 메서드의 첫 번째 인자로 클래스 자체($cls$)를 받는 데코레이터이다.
* **활용:** 인스턴스를 생성하지 않고 클래스 수준에서 호출하며, 주로 객체 생성을 담당하는 **Factory Method**를 구현할 때 사용한다.

### **바다코끼리 연산자 (Walrus Operator, `:=`)**
* **개념:** 변수에 값을 할당함과 동시에 그 값을 식(Expression)으로 반환하는 연산자이다.
* **활용:** `if`나 `while` 조건문 안에서 계산과 할당을 동시에 처리하여 코드의 중복을 줄인다.

## 🧪 4. TDD (Test Driven Development)
### **TDD란?**
실제 비즈니스 코드를 작성하기 전에 **실패하는 테스트 코드를 먼저 작성**하는 개발 방법론이다.

### **주요 특징**
* **Red-Green-Refactor:** 실패(Red) → 성공(Green) → 개선(Refactor)의 짧은 주기를 반복한다.
* **안정성:** 테스트를 염두에 두고 설계하므로 모듈 간 결합도가 낮아지고, 리팩토링 시 사이드 이펙트를 방지한다.

---

## 🏗️ 5. Service Design Pattern
### **Service Layer란?**
애플리케이션의 핵심 비즈니스 로직을 담당하는 계층으로, API 컨트롤러와 데이터 접근 계층 사이에서 가교 역할을 한다.

### **주요 특징**
* **관심사 분리:** 컨트롤러는 HTTP 요청만 처리하고, 서비스는 도메인 로직만 수행한다.
* **재사용성:** 동일한 비즈니스 로직을 다양한 진입점(API, CLI 등)에서 호출할 수 있다.

---

## 📦 6. Repository Design Pattern
### **Repository 패턴이란?**
데이터 저장소(DB)에 접근하는 로직을 추상화하여, 비즈니스 로직이 특정 DB 기술에 종속되지 않게 하는 패턴이다.

### **주요 특징**
* **추상화:** 로직에서는 데이터를 DB에서 가져오는지 파일에서 가져오는지 알 필요는 없다.
* **테스트 용이성:** 실제 DB 대신 메모리 기반의 가짜 객체(Mock)를 사용하여 테스트하기 편리하다.

---

## 🔄 7. DTO (Data Transfer Object)
### **DTO란?**
계층 간(예: Service ↔ Controller) 데이터를 전달하기 위해 사용되는 순수 데이터 객체이다.

### **주요 특징**
* **엔티티 보호:** 데이터베이스 스키마와 직결된 Entity를 외부에 직접 노출하지 않아 보안을 강화한다.
* **데이터 정제:** 클라이언트가 필요한 데이터만 골라내거나 가공하여 전달하는 '필터' 역할을 수행한다.
